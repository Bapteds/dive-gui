# Brain: DIVE Turbinen project knowledge base

> Shared memory of the agents (Claude Code, Codex…) and the developers.
> Rules entry point: `AGENTS.md` (imported by `CLAUDE.md`), plus zone rules in `apps/web/`, `apps/api/`, `apps/api/scripts/`, `packages/shared/`. This file indexes the rest.
> Economy principle: **load only what the task needs**. Each file stands alone; codemaps and `INDEX.md` are references to search, not to read end to end.

## 1. Map

| Path | Content | When to read it |
|---|---|---|
| `STATUS.md` | Current state: branch, last work, verification, environments, pitfalls, questions waiting for the user | **Always**, at the start of a session |
| `changelog/YYYY-MM.md` | Log of every change (newest first); rules in `changelog/README.md` | Start of a session (current month); history of an area |
| `INDEX.md` | **Every file of the repository, one line each** (role + codemap sheet). Generated by `codemap/build-index.py` | Find a file, know what it is for |
| `codemap/README.md` | Detailed per-file sheets (role, exports, dependencies, pitfalls) | Understand a file in depth |
| `features/README.md` | One end-to-end sheet per feature | Understand or change a feature |
| `playbooks/README.md` | Step-by-step recipes for routine changes | Before adding an endpoint, a migration, an env var, a page, a solver, a chamber input, changing geometry, deploying |
| `architecture/overview.md` | System view: monorepo, runtime, data flows, security | First contact, cross-cutting task |
| `architecture/api-routes.md` | Every REST and WebSocket route | Add or consume an endpoint |
| `architecture/data-model.md` | Prisma model, migrations, related business rules | Touch the DB or permissions |
| `architecture/storage-layout.md` | Disk layout under `STORAGE_DIR`, lifecycle, path safety | Touch case files, meshes, runs, caches |
| `architecture/configuration.md` | Every environment variable (API, web, MCP) | Configure, deploy, add a setting |
| `architecture/frontend.md` | Bootstrap, routing, session, TanStack Query, UI primitives, tokens | Any frontend work |
| `conventions/workflow.md` | Session protocol, spec → test → code → changelog cycle, Git | **Always** before changing anything |
| `conventions/code-style.md` | Backend / frontend / Python code patterns, naming, errors | Writing code |
| `conventions/testing.md` | Suites, commands, isolation, CI, test templates | Writing or running tests |
| `conventions/frontend.md` | UI skill sequence, brand charter, tokens, UI definition of done | **Before any JSX/CSS** |
| `conventions/vocabulary.md` | CFD / OpenFOAM / chamber glossary, approved naming rules | Writing a visible string, reading a spec |
| `design/design-system.md` | Visual and component contract (formerly `DESIGN.md`) | Any UI work |
| `design/product.md` | Product positioning, users, principles (formerly `PRODUCT.md`) | UX decisions, tone, priorities |
| `operations/installation.md` | Step-by-step install, update and deployment (formerly `INSTALLATION.md`) | Install, deploy, troubleshoot the server |
| `known-issues.md` | Known bugs (audit + status), code-reading findings, open threads, environment limits | Before fixing a bug or touching a fragile area |
| `decisions.md` | Register of structural decisions (what, when, why) | Before challenging a technical or product choice |
| `specs/` | Approved design specs (`YYYY-MM-DD-<topic>-design.md`) | Context of a feature, before writing a new one |
| `plans/` | Detailed implementation plans of the big topics | Resume or audit an implementation |
| `assets/chamber-parameter-map.html` | Interactive mind map of the chamber parameters (2026-08-04, model v2) | Explore parameter relations |

Only `README.md` (technical reference for humans, GitHub convention), `AGENTS.md` and `CLAUDE.md` stay at the repository root. Domain reference material: `documents/` (Gen Dim v3 workbook, semi-spiral spec, BC profiles, turbulence notes), cited by the code.

## 2. Reading paths by task

- **Fix a bug**: `STATUS.md` → `known-issues.md` → feature sheet → codemap sections of the files involved → `conventions/testing.md`.
- **New feature**: `STATUS.md` → `conventions/workflow.md` → neighboring feature sheets → relevant `architecture/*` → spec to write in `specs/` → playbooks.
- **Routine change** (endpoint, migration, env var, page, solver, chamber input, geometry, deploy): the matching `playbooks/*.md`.
- **UI work**: `apps/web/AGENTS.md` → `conventions/frontend.md` → `design/design-system.md` → `architecture/frontend.md` → `codemap/web-*.md`.
- **Chamber Creation**: `features/chamber-creation.md` → `conventions/vocabulary.md` §1 and §3 → `apps/api/scripts/AGENTS.md` → `codemap/api-scripts.md` → specs `specs/2026-08-*` and `2026-09-*`.
- **Deployment / environment**: `playbooks/deploy-and-update.md` → `architecture/configuration.md` → `operations/installation.md` → `STATUS.md` §3.

## 3. Maintenance (mandatory, by the agent, in the same change)

| Event | Files to update |
|---|---|
| Any change to code, config, script or test | `changelog/YYYY-MM.md` (new entry) |
| File created, deleted, renamed; export added or changing role | the `codemap/*.md` sheet of the area, then `python brain/codemap/build-index.py` (regenerates `INDEX.md`) |
| Visible behavior, business rule, endpoint or flow of a feature changed | `features/<feature>.md` (+ `architecture/api-routes.md` for an endpoint) |
| New feature | new `features/<feature>.md` sheet + a line in `features/README.md` |
| Prisma model or migration | `architecture/data-model.md` |
| Environment variable added or changed | `architecture/configuration.md` (+ `.env.example`) |
| New persistent folder or file on disk | `architecture/storage-layout.md` |
| New routine procedure, or a playbook step that no longer matches the code | `playbooks/*.md` |
| Rule specific to one area (web, api, scripts, shared) | the zone `AGENTS.md` (`apps/web/`, `apps/api/`, `apps/api/scripts/`, `packages/shared/`) |
| Structural decision taken with the user | `decisions.md` + a `Decision` changelog entry |
| Bug found or fixed | `known-issues.md` |
| End of session or state change (branch, PR, verification, open threads) | `STATUS.md` (rewrite the snapshot, do not stack) |
| New convention or rule given by the user | the relevant `conventions/*.md` file |

Writing rules: English, identifiers in backticks, no line numbers (they drift), factual, dated (`YYYY-MM-DD`) when the information can go stale. Fix or delete wrong information instead of stacking a contradiction.
