# Vocabulary and naming rules

> Glossary of the domain (CFD, OpenFOAM, turbines) and of the application's concepts, plus the naming rules validated by the user.
> Principle: **visible renames are DISPLAY changes only**. Internal keys, enums, save snapshots and cache keys never change.

## 1. Validated naming rules (non-negotiable)

| Rule | Detail |
|---|---|
| **"outlet" = the FLUID EXIT** | Never the middle cylinder. In a build without vanes, the outlet is further downstream; in a build with vanes, the guide vanes occupy the middle zone. Explicit correction by the user (2026-09-02). Open question: the OpenFOAM `outlet` patch of the Closed generator design without vanes is placed on the middle cylinder (see `brain/known-issues.md` §6). |
| Chamber inputs X1 to X4 | Displayed as **Runner Ø (mm)**, **Head (m)**, **Q_max (m³/s)**, **Power (kW)**. Internal keys `x1`..`x4` unchanged. Relation: Power = 0.9 · 9.81 · Head · Q_max. |
| Chamber variants | "Design" menu: **Closed generator** (`variant: 'stepped'`) and **With cone** (`variant: 'hollow'`). No explanation after the label. |
| "chamber", not "box" | In every visible string. The KO/WARN texts of the Python builder still say "box" (sweep not requested). |
| Named parts | **runner case** (1st cylinder, `dFirst`, label "Runner case Ø (mm)"), **middle cylinder** (`dMiddle`, label "Guide vanes Ø (mm)"), **cone** (the open cut of the hollow variant), **generator** (central cylinder). |
| Accepted near-collision | "Runner Ø (mm)" (X1, the runner wheel) and "Runner case Ø (mm)" (`dFirst`, the casing) refer to two different things: confirmed by the user. |
| Language | Code, comments, commits, UI strings and the brain are in English. Only the changelog history written before 2026-09-28 stays in French. |

## 2. Application concepts

| Term | Meaning |
|---|---|
| **Project** | CFD workspace: one OpenFOAM case + its mesh library + its runs. Visible to its owner, its collaborators and any super-admin (otherwise 404). |
| **Owner / collaborator** | The owner (or a super-admin) can delete the project and manage collaborators; a collaborator works in the project. |
| **Super-admin** | Role `SUPER_ADMIN`; the seeded account is `isProtected`: it can never be deleted, demoted or deactivated. |
| **Case** | The project's OpenFOAM folder (`0/`, `constant/`, `system/`) under `STORAGE_DIR/projects/<id>/case/`. |
| **Mesh library** | Meshes imported into a project, stored under a readable **slug** (no more UUIDs). Sources for merges and assemblies. |
| **Merge** | Conformal merge of meshes (`mergeMeshes` + `stitchMesh`). |
| **Assembly** | Multi-part 3D assembly: rigid placement (6-DOF gizmo), optional non-conformal coupling, base = the case mesh; reversible (Disassemble). |
| **Run** | Execution of a solver (serial or MPI parallel) with live log and residuals; statuses `queued/running/succeeded/failed/stopped/diverged…` (see `packages/shared`). |
| **Meshing session** | Session of the Meshing page: STL (or FMS) → snappyHexMesh or cfMesh → polyMesh; can be duplicated and renamed. |
| **Chamber build** | Chamber geometry generated by `buildChamber.py` (CadQuery) from the X1..X4 inputs; cached by parameter hash; exportable (STL/GLB/STEP) and transferable to Meshing. |
| **Saved build (chamber save)** | Named snapshot of the chamber form inputs (load/save/rename/duplicate/delete). |
| **Template** | Reusable, tagged case file(s), applicable to a project. |
| **Easy / Advanced** | Two editing modes: guided form vs raw editor (CodeMirror). |

## 3. Chamber Creation: geometric terms

| Term | Meaning |
|---|---|
| **Gen Dim v3** | Empirical model of the generator dimensions (Ø, height, dome) from X1..X4; source of truth: `documents/Gen Dim v3 Only Calculator (standalone).xlsx`, implemented by `computeChamberGeneratorDims` in `packages/shared`. |
| **Simplify Generator** | Option (hollow variant only): generator as a strict cylinder going through the top of the chamber, without a dome. |
| **Guide vanes** | Ring of guide vanes replacing the middle cylinder; stagger angle `vaneAngleDeg` (default 50°, range 45 to 55). Checked by default. |
| **Hub / shroud** | Inner and outer surfaces of the guide vane channel; separate OpenFOAM patches `hub` and `shroud`. |
| **Torque feet** | Torque feet (leg + gusset plank), can be disabled. |
| **Chamfer** | Chamfer of the chamber, can be disabled without touching the rest of the geometry. |
| **Semi-spiral casing** | Option (both designs, `semiSpiral`): the chamber footprint follows the optimised semi-spiral outline. Its parts: the **spiral** (6 lines L1..L6), the **nose** (3-line tongue tip L7..L9, 200 mm from the widest part), the **plank** (50 mm slab from the nose tip, tangent to the generator / cone). Nose + plank = the **`tongue`** patch (internal name, never renamed). "Casing flow velocity" = `spiralFlowVelocity` (the tool's `c_flow`). Status of the derived rows: `from spiral`. |
| **Cone chamfer** | Option (both designs, `coneChamferEnabled` / `coneChamferSize`): 45° **foot** chamfer on the lower outer edge of the LE part (the Closed-generator last cylinder or the cone outer wall) where it stands on LEB; the part is widened by the size above it so the foot stays on LE Ø/2. Kept the name "Cone chamfer" in Closed generator too. Never call it just "Chamfer": that is the chamber's corner chamfer (`chamferEnabled`). The top-rim version (inner top edge of the cone, 2026-09-29 morning) was removed. |
| **partScale** | Uniform scale of the inner assembly (chamber and axis fixed). |
| **Structural relations** | Toggleable empirical identities (H Kammer = LEB + LEOW, LEB = 2 × HLE, P11 = 2 × P10…) with Min/Max/Exact constraints. Original German labels: H Kammer (chamber height), LEB, LEOW, HLE. |
| **Refusal vs warning** | Refusal (422, build blocked) when a part overflows the chamber; warning (build delivered, message surfaced in the UI) for edge cases (e.g. non-monotonic hub shoulder). |
| **50 mm rounding** | Empirical dimensions are rounded to a multiple of 50 mm. |

## 4. OpenFOAM and CFD

| Term | Meaning |
|---|---|
| **ESI OpenFOAM v2406** | openfoam.**com** edition used by the API in production (v2606 is also installed on the server). Do not confuse with OpenFOAM.org (v11/v12): different CLI syntaxes. |
| `0/`, `constant/`, `system/` | Initial fields / mesh and physical properties / numerical control of a case. |
| `polyMesh`, `boundary` | OpenFOAM mesh; `constant/polyMesh/boundary` lists the patches. Rule: `0/*.boundaryField` must cover every patch. |
| **Patch** | Named, typed boundary surface (`wall`, `patch`, `inlet`, `outlet`, `empty`, `cyclicAMI`…). |
| `controlDict`, `fvSchemes`, `fvSolution` | Run control, discretization schemes, linear solvers; generated in a "model-aware" way (turbulence ⇒ numerics). |
| **snappyHexMesh** / **cfMesh** (`cartesianMesh`) | The two meshers of the Meshing page; cfMesh merges several STLs into a single `.fms`. |
| `decomposePar` / `mpirun` / `reconstructPar` | Parallel execution pipeline; global core budget `SOLVER_TOTAL_CORES`. |
| **MRF / Frozen Rotor**, **Moving Rotor** (forced or free sixDoF) | Rotor models of the boundary conditions flow (`MRFProperties`, `dynamicMeshDict`). |
| **Wall functions** | Wall conditions chosen automatically according to the turbulence model. |
| **k / ε / ω** | Turbulence variables; the turbulence calculator derives the `0/` seeds from them. |
| **topoSet** | Cell/face selection utility (`system/topoSetDict`, Basic or Manual mode). |
| **CGNS** | Exchange format; input (CGNS→Foam conversion through VTK) and output (CFD-Post export through `pvbatch`). |
| **CFD-Post** | Ansys post-processor, target of the single-file transient CGNS export. |
| **Non-conformal couple** | Coupling of non-conformal interfaces used by Assemble: textual retyping of the chosen patches to `cyclicAMI` in `constant/polyMesh/boundary` (no call to `createNonConformalCouples`, an OpenFOAM.org utility absent from ESI). |
| **BC object types** | Turbine, Pipe, DraftTube, Chamber: preset boundary condition profiles (`documents/old/*_BCs*.txt`). |
