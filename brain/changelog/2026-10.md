## 2026-10-01 · Feature · Chamber: Length is a Parameters-table row with Min / Max / Exact in both modes
**Area**: chamber (shared model, API, web, optimisation) · **Commits**: branch `feat/chamber-length-row` (from `docs/server-runtime`)
**Summary**: Brief `2026-09-30-chamber-spiral-and-optimisation-fixes` item 2, spec `2026-10-01-chamber-length-row-design.md` (approved). The box Length was a form field without the spiral (`lengthOverride`, blank = 2 × B Kammer) and a separate table row with the spiral (`spiralLength`). It is now one model row, `length`, right after B Kammer: the always-on identity `= 2 × B Kammer` (no fit, Confidence "-"), with Min / Max / Exact and the usual statuses in both modes. With the spiral on it still behaves as before (Max limits the spiral, Min extends the inlet channel, Final = the spiral's length). Length is pickable in optimisation studies for non-spiral base designs.
**Details**:
- Shared: `CHAMBER_OUTPUT_KEYS` gains `length` (13 outputs); `ChamberForm` `'identity'`, `ChamberRelation.fixed`, nullable `cvError` / `confidence`; new `normaliseChamberLength` (old saves and clients: plain-box `lengthOverride` → Length Exact, spiral `spiralLength` → `constraints.length`, the field each mode ignored is dropped); `applyChamberSpiralToOutputs` takes the spiral summary for the Length statuses; `studyPickableKeys` keeps Length out of spiral base designs.
- API: the body is normalised first; `params.length` comes from the `length` output (same number as `lengthOverride ?? 2 × width`); the special Length inverted-range branch is replaced by the generic one (same wording).
- Web: the `Length (mm)` form field and the `autoLengthMm` prop are removed; the table's special spiral Length row is gone (Length is an ordinary row, Model "-" with the spiral); `ChamberPage` drops its `spiralLength` state; saves and study hand-offs load through `chamberInputToConstraints`.
- **Cache**: build hashes unchanged (frozen in `chamber.test.ts`: plain `97ccaaee672f8851`, `lengthOverride` 12000 `a2fe3df7d2b5dcb9`, spiral `22df8fb40911cd93`); spiral inputs unchanged. **No builder change: no `$STORAGE_DIR/chamber/*` or `chamber-spiral/` purge.**
- UI skill sequence not run: no new visual element (an existing table row reused, a field removed); tokens and AA unchanged (deviation allowed by `conventions/frontend.md` §1).
- Nothing here needs OpenFOAM or CadQuery; browser pass not done.
**Files**: `packages/shared/src/index.ts`, `apps/api/src/modules/chamber/chamber.service.ts`, `chamber.schemas.ts`, `apps/web/src/features/chamber/{ChamberInputsForm,ChamberOutputsTable}.tsx`, `chamberForm.ts`, `apps/web/src/pages/ChamberPage.tsx`, tests (`chamberModel`, `studyModel`, `chamber` API tests; web chamber + `StudyCreateForm` tests), brain (spec, codemaps, `features/chamber-creation.md`, `features/optimisation.md`, `decisions.md`, `STATUS.md`, `stepbystep/`).
**Tests**: `npm run build:shared`; API `chamber`, `chamberModel`, `chamberSaves`, `chamberPatchTypes`, `studyModel`, `studies`, `studyRunner` 201/201; full API 784/786 (the 2 failures are the known Windows-flaky meshing Stop / atomic-status tests, `known-issues.md` §6); web full 331/331; `npm run typecheck` clean; eslint on the touched areas clean.
